# Vakre Barn

- URL: vakrebarn.no
- Category: Baby, kids & toys / groceries & pet supplies
- Tier: phase1-scrape
- Chosen method: none functional yet — real check found robots.txt open (identical permissive template to Familiebutikken/DressMyKid, same platform vendor) but **no JSON-LD at all**: checked 3 different real product pages (`/products/blomsterkjole-shadow-gammelrosa`, `/products/cardigan-sofus`, `/products/bukse-mauve-chalk`, and independently re-confirmed on `/products/babylue-lys-rosa`, `/products/kortermet-body-mvolang`, `/products/silikonsmekke` — also checked for `itemtype` microdata and `og:price` Open Graph tags, both absent too) and none contain any `ld+json` script tag or other `schema.org`/price-bearing markup, unlike its same-platform siblings Familiebutikken/DressMyKid which both have it. scrapeSource()'s generic JSON-LD parser has nothing to grab here, so it can't be onboarded as-is without a new extraction path.
- Alternatives: a non-JSON-LD scrape (parsing the page's own HTML/price display directly) is theoretically possible since robots.txt doesn't forbid it, but that's new parsing code beyond what scrapeSource()/productOffer() do today — worth confirming in Phase B whether this is a per-shop feature flag on the same platform (fixable by the shop enabling it) before writing a bespoke parser.
- Status: not viable 2026-07-25 — sitemap reachable, but a sampled discovery crawl through `discoverSource()` produced no priced JSON-LD offer on any page tried (several sub-sitemap/UA/path-filter combinations). Nothing to ingest until the shop's markup changes.
- Notes: Baby & kids clothing (0–6y) — no existing pricy.no category fits regardless of ingestion method. Same vendor platform as Familiebutikken/DressMyKid (same robots.txt template) but structured-data support appears to be off for this particular shop instance — worth asking the shop or re-checking after a cache-buster/different page template (e.g. a collection page) before writing custom scrape code.
